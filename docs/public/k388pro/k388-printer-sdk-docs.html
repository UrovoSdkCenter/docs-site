概述

SDK 简介

K388 Printer SDK 是面向 Urovo K388 / K388Pro 本机内置打印机 的 Android 开发包。对外入口为 com.urovo.printer.UPrinterManager。打印指令为 CPCL，坐标单位为点（dot），203 dpi 下约 8 点 = 1 mm。

当前 getSDKVersion() 返回：Urovo K388 Printer SDK v1.0.0。组包实现 version() 返回：V1.5。

本 SDK 不使用 TCP 9100，通过本机 LocalSocket（PrinterLocalServerSocket）与打印服务通信。

版本变更

当前文档对应 SDK v1.0.0。print 工程内未提供独立 ChangeLog / Release notes。如需补充历史版本（新增/变更/废弃 API），请提供后更新本节。

核心能力

  • 连接本机打印机，查询状态（缺纸、开盖等）
  • 组 CPCL 页面：文字、线条、框、一维码、二维码、图片
  • 下发原始字节或 GBK 文本
  • 打印参数与持久化寄存器设置（黑度、模式、多张延时、回退）
  • RFID 读写与功率设置
  • 固件版本查询与固件升级

适用场景

  • 设备侧标签 / 票据打印
  • 扫描后现场打印条码或二维码
  • 标签 RFID 写入后读回校验
  • 产线或运维场景的固件升级

环境要求

项目要求
平台Android
最低版本API 24（Android 7.0）
语言Java 8
依赖本机打印服务；模块 minSdk 24，compileSdk 34
鉴权无

接入

获取 SDK

将 print 模块编译产物（AAR 或 jar）引入应用。常用方式：

gradle
implementation project(':print')

或拷贝 jar，例如：

gradle
implementation files('libs/UK388PrintLibrary_v2.3.1.jar')

生成 jar（模块内已注册 makeJar）：

bash
./gradlew :print:compileDebugJavaWithJavac :print:makeJar

输出目录：print/build/libs/。

工程配置

  • print 模块 AndroidManifest.xml 未声明额外权限；应用按业务需要自行申请存储（固件文件）等权限。
  • 混淆时需 keep com.urovo.printer.**（参见模块 proguard-rules.pro）。
  • 无 API Key / 鉴权配置。

初始化

java
UPrinterManager printer = UPrinterManager.getInstance(context);
// 或
UPrinterManager.initialize(context);
UPrinterManager printer = UPrinterManager.getInstance();

首次必须使用带 Context 的入口。之后可 getInstance()。

快速开始

java
UPrinterManager printer = UPrinterManager.getInstance(context);
try {
    printer.connect();
    printer.pageSetup(384, 240);
    printer.drawText(16, 16, "K388", 2, 0, 0, false, false);
    printer.drawBarCode(16, 64, "123456789012", 1, 0, 2, 72);
    byte[] data = printer.printByte(0, 1);
    boolean ok = printer.printByData(data);
} catch (PrinterException e) {
    e.printStackTrace();
} finally {
    printer.disconnect();
}

步骤：getInstance → connect → pageSetup / draw* 组页 → printByte 取数据 → printByData 发送 → disconnect。

成功标志：printByData 返回 true，打印机出纸。pageSetup / drawText 不会单独出纸。

发送打印数据

UPrinterManager.printByData

将字节写入打印服务。组页完成后必须调用本方法（或 printByText）才会打印。

签名

java
boolean printByData(byte[] data)
参数类型必填说明
databyte[]是打印数据，通常来自 printByte

返回值

true 发送成功；未连接、升级中返回 false。

异常 / 错误码

无。

示例

java
byte[] data = printer.printByte(0, 1);
boolean ok = printer.printByData(data);
MethodDescription
boolean printByText(String text)按 GBK 编码发送文本或 CPCL 字符串

应用侧也可用同库 GZIPFrame.codec(byte[]) 压缩后再 printByData（工具方法，非 Manager 接口）。

示例

文本与条码标签

java
UPrinterManager printer = UPrinterManager.getInstance(context);
printer.connect();
printer.pageSetup(384, 240, 0, 1);
printer.setContrast(2);
printer.drawText(16, 16, "物料编码", 2, 0, 1, false, false);
printer.drawBarCode(16, 56, "ABC123456789", 1, 0, 2, 72);

byte[] data = printer.printByte(0, 1);
printer.printByData(data);
printer.disconnect();

要点：标签纸常用 skip=1（缝隙检测）。

图片打印

java
printer.connect();
printer.pageSetup(bitmap.getWidth(), bitmap.getHeight());
printer.drawGraphic(0, 0, bitmap);
byte[] data = printer.printByte(0, 1);
byte[] gzip = GZIPFrame.codec(data);
printer.printByData(gzip);
printer.disconnect();

要点：图片页必须用 printByte；大数据可先 GZIP。

RFID 写入

java
boolean ok = printer.rfidWrite(1, 0x00000000, 4, epc, epc.length);
String code = printer.rfidWriteWithResp(1, 0x00000000, 4, epc, epc.length);
byte[] buf = new byte[epc.length];
printer.rfidRead(1, 0x00000000, 4, buf, buf.length);

要点：从 offset=4 写 EPC 区时不会自动更新 PC 长度字段；长度变化需自行更新 PC。

注意事项与 FAQ

注意事项

  • draw* 只组页，必须 printByData / printByText 才会打印。
  • 文本按 GBK 编码。
  • 页面宽度不要超过打印头可打宽度（常见约 384~400 点）。
  • 固件升级、RFID、打印请避免阻塞 UI 线程。
  • 升级过程中禁止 connect / 打印 / 改设置。
  • 本 SDK 面向本机打印服务，不是网络 9100 端口，也不是 ZPL 组包库。

FAQ

Q: 调用了 drawText 为什么没出纸？

A: 还需 printByte（或 print）再 printByData。

Q: 是否支持 ZPL？

A: 组页 API 为 CPCL。若固件接受 ZPL，仅可用 printByText/printByData 发送原文，SDK 不封装 ZPL。

Q: printByData 未连接会怎样？

A: 返回 false，不会抛异常。

Q: 图片右侧出现空白？

A: 页宽可能大于可打宽度，尝试将宽度降到约 384 点，并确认标签方向与 pageSetup 一致。

Overview

Introduction

K388 Printer SDK is an Android library for the onboard printer on Urovo K388 / K388Pro. The public entry class is com.urovo.printer.UPrinterManager. Print commands are CPCL. Coordinates are in dots; at 203 dpi about 8 dots = 1 mm.

getSDKVersion() returns Urovo K388 Printer SDK v1.0.0. Page-builder version() returns V1.5.

This SDK does not use TCP port 9100. It talks to the local print service through a LocalSocket named PrinterLocalServerSocket.

Version history

This document matches SDK v1.0.0. The print module does not include a standalone ChangeLog. Provide historical notes (added / changed / removed APIs) if they should appear here.

Key Features

  • Connect to the onboard printer and query status (paper, cover)
  • Build CPCL pages: text, lines, boxes, 1D/2D barcodes, images
  • Send raw bytes or GBK text
  • Job settings and persistent registers (darkness, mode, multi-copy delay, rewind)
  • RFID read/write and power
  • Firmware version query and upgrade

Use Cases

  • On-device label / receipt printing
  • Print barcodes or QR codes after a scan
  • Write RFID then read back for verification
  • Firmware upgrade in production or maintenance

Integration

Obtain the SDK

Add the print module AAR or JAR.

gradle
implementation project(':print')

Or copy a JAR:

gradle
implementation files('libs/UK388PrintLibrary_v2.3.1.jar')

Build a JAR (makeJar is registered in the module):

bash
./gradlew :print:compileDebugJavaWithJavac :print:makeJar

Output: print/build/libs/.

Project Setup

  • The module AndroidManifest.xml declares no extra permissions. Request storage (firmware file) in the app if needed.
  • Keep com.urovo.printer.** in ProGuard (see proguard-rules.pro).
  • No API key or authentication.

Initialization

java
UPrinterManager printer = UPrinterManager.getInstance(context);
// or
UPrinterManager.initialize(context);
UPrinterManager printer = UPrinterManager.getInstance();

The first call must pass a Context. Later calls may use getInstance().

Quick Start

java
UPrinterManager printer = UPrinterManager.getInstance(context);
try {
    printer.connect();
    printer.pageSetup(384, 240);
    printer.drawText(16, 16, "K388", 2, 0, 0, false, false);
    printer.drawBarCode(16, 64, "123456789012", 1, 0, 2, 72);
    byte[] data = printer.printByte(0, 1);
    boolean ok = printer.printByData(data);
} catch (PrinterException e) {
    e.printStackTrace();
} finally {
    printer.disconnect();
}

Flow: getInstance → connect → pageSetup / draw* → printByte → printByData → disconnect.

Success: printByData returns true and paper feeds. pageSetup / drawText alone do not print.

Examples

Text and barcode label

java
UPrinterManager printer = UPrinterManager.getInstance(context);
printer.connect();
printer.pageSetup(384, 240, 0, 1);
printer.setContrast(2);
printer.drawText(16, 16, "Item Code", 2, 0, 1, false, false);
printer.drawBarCode(16, 56, "ABC123456789", 1, 0, 2, 72);
printer.drawText(16, 140, "ABC123456789", 1, 0, 0, false, false);
byte[] data = printer.printByte(0, 1);
printer.printByData(data);
printer.disconnect();

Use skip=1 (gap sense) for typical labels.

Image print

java
printer.connect();
printer.pageSetup(bitmap.getWidth(), bitmap.getHeight());
printer.drawGraphic(0, 0, bitmap);
byte[] data = printer.printByte(0, 1);
byte[] gzip = GZIPFrame.codec(data);
printer.printByData(gzip);
printer.disconnect();

Image pages must use printByte. Large jobs may GZIP first.

RFID write

java
boolean ok = printer.rfidWrite(1, 0x00000000, 4, epc, epc.length);
String code = printer.rfidWriteWithResp(1, 0x00000000, 4, epc, epc.length);
byte[] buf = new byte[epc.length];
printer.rfidRead(1, 0x00000000, 4, buf, buf.length);

Writing EPC at offset 4 does not update the PC length field automatically.

Notes & FAQ

Notes

  • draw* only builds the page; you must call printByData / printByText to print.
  • Text is encoded as GBK.
  • Keep page width within the printable width (often about 384–400 dots).
  • Avoid blocking the UI for firmware upgrade, RFID, and print I/O.
  • During upgrade, do not connect, print, or change settings.
  • This SDK targets the onboard print service, not TCP 9100, and is not a ZPL builder.

FAQ

Q: I called drawText but nothing printed.

A: Also call printByte (or print) then printByData.

Q: Is ZPL supported?

A: Page APIs are CPCL. If firmware accepts ZPL, you may send raw text with printByText/printByData; the SDK does not wrap ZPL.

Q: What if printByData is called while disconnected?

A: It returns false and does not throw.

Q: Blank space on the right of an image?

A: Page width may exceed the printable width. Try about 384 dots and match label orientation to pageSetup.
