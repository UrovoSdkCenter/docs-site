    1、Overview

    1.1、Introduction

    UBX UHF RFID SDK (URFIDLibrary) is an Android UHF RFID library delivered as an AAR. It abstracts reader communication and provides inventory, tag access, configuration, firmware upgrade, and peripheral management.

    Document version: V2.25

    1.2、Version history

    2025-12-30 （URFIDLibrary-v2.5.1230.aar）

    1. setInventorySceneMode - New Inventory Scene Modes

    Added two new reading modes: • Cycle Count Mode: Deduplicated inventory counting mode • Max Range Mode: Maximum read distance mode

    2. Data Callback Parameter Type Change

    The onInventoryTag callback method signature has been updated:

    java
    Previous:
onInventoryTag(String EPC, String Data, String rssi);
Updated:
onInventoryTag(String EPC, String Data, int rssi);

    Note: The rssi parameter type changed from String to int.

    3. RfidProfile Enumeration - Miller Configuration Return Type Change

    The Miller configuration getter in RfidProfile enumeration now returns int type instead of String.

    4. New Method: getSupportProfileList()

    Added a new method to retrieve the list of supported Profile combinations: getSupportProfileList()

    5. New Method: getSupportFrequencyBandList()

    Added a new method to retrieve the list of supported Frequency Region combinations: getSupportFrequencyBandList()

    6. New Method: getSupportWorkRegionList()

    Added a new method to retrieve the list of supported Country Code combinations: getSupportWorkRegionList()

    7. Enhanced Module Type Identification: getModuleType()

    Enhanced the method for retrieving the current module type. This method can be used to differentiate supported Profiles:

    java
    int getModuleType()

    Added a new method to retrieve the reader device type: getReaderDeviceType() ReaderDeviceType Enumeration Values:

    9. New Method: setInventoryPhaseFlag(boolean flag)

    Added a new method to enable or disable the return of phase and frequency information: setInventoryPhaseFlag(boolean flag)

    10. Callback Registration Method Update

    Recommended: Use addDataCallback() instead of the deprecated registration method.

    The rfidManager.release() method has been removed. Use the following method instead: RFIDSDKManager.getInstance().release();

    1.3、Core capabilities

    • Lifecycle: integrated/UART and Bluetooth init, connection, release
    • Inventory: continuous, timed, single-shot, scene modes, mixed memory bank query
    • Tag access: Gen2 read/write/lock/kill, mask ops, TID-based access
    • Reader config: power, profile, region, antenna multiplexing
    • Firmware upgrade: local and online via RFUpgradeManager
    • Peripherals: Bluetooth/UART sled barcode, battery/offline, key events

    1.4、Use cases

    • Warehouse/asset batch inventory
    • Single-tag read/write and EPC rewrite
    • PDA and Bluetooth RFID sled applications
    • Fixed reader multi-antenna inventory

    java
    RFIDSDKManager.getInstance().init(context, status -> {
    if (!status) return;

RfidManager rfid = RFIDSDKManager.getInstance().getRfidManager();
rfid.addDataCallback(new DataCallback() {
    @Override public void onInventoryTag(ReadTag readTag) { /* EPC: readTag.epcId */ }
    @Override public void onInventoryTagEnd() { }

rfid.startInventoryWithTimeout(300);

// stop: RFIDSDKManager.getInstance().getRfidManager().stopInventory();
// exit: RFIDSDKManager.getInstance().release();

    Note: Call addDataCallback, startInventoryWithTimeout, stopInventory, and release outside the init callback; the callback should only handle connection success or failure.

    4.2.1、startInventoryWithTimeout

    Starts inventory. Parameter timeout is in seconds. When the timeout elapses, inventory stops automatically and onInventoryTagEnd() is invoked. Stop early with stopInventory().

    Results are delivered via addDataCallback().

    Returns

    Success: RfidErrorConstants.SUCCESS (int)

    Failure: other codes (see Error codes and types).

    Example

    java
    RFIDSDKManager.getInstance().getRfidManager().startInventoryWithTimeout(300);

    UBX UHF RFID SDK（URFIDLibrary）是面向 Android 平台的超高频（UHF）RFID 开发库，以 AAR 形式交付（URFIDLibrary-xxxxxx.aar），封装与 RFID 读写模块的通信细节，为应用层提供初始化、盘点（Inventory）、标签读写、参数配置、固件升级及蓝牙/UART 外设管理等能力。

    Tari/PIE/BLF/Miller 简要说明：

    Parameter Explanation Introduction

    TariA类参考时间间隔,定义了读写器发送给标签的最基本时间单位。 前向链路的基石，决定了通信的基准速率。值越小，数据速率越高。
    PIE脉冲间隔编码,读写器向标签发送数据时采用的编码方式。 PIE值大小，核心是指其基准时间间隔Tari的数值，（具体为Tari）越小，数据速率越高，但信号能量可能不足，导致读取距离变短或稳定性下降；反之，Tari越大，通信越稳健，读取距离可能更远，但速率会降低。
    BLF反向散射链路频率,决定标签返回数据给读写器的速率。 反向链路的时钟。BLF越高，读取速度越快，但信号衰减也越快，读取距离可能受影响。
    Miller密勒调制副载波,标签向读写器返回数据时采用的一种编码方式 提高抗干扰能力，但会降低有效数据速率（Miller-2/4/8，数字越大越稳健，读取速度越慢）。

    4.3.16、addMaskBits

    添加盘点时的过滤参数,添加该掩码参数后，盘点时只会盘点到设置了对应掩码的标签。过滤掉不属于掩码内的标签。 可以多次添加不同的掩码数据。

    void addMask(int memMask, int startMask, int lenMask, String datasMask);
    参数类型说明
    memMaskint过滤区域：
    TAG存储区：; MemoryBank.RESERVED(RESERVED); MemoryBank.EPC (EPC); MemoryBank.TID (TID); MemoryBank.USER (USER)
    startMaskint起始地址，这里地址的参数跟其他方法参数有差异,数据起始位是从16进制字符串的字符所在位置算起：
    比如要掩码EPC的数据：
    EPC :E280FE9889895674
    如果要掩码其中的"FE98"那么这里的起始位置则填 12（bits） (因为EPC前面还有CRC+PC)
    如果是TID或USER：
    USER(或TID)：00001234567898762345
    如果要掩码其中的"56789876"那么这里的起始位置填 32（bits）
    lenMaskint掩码长度，这里长度的参数跟其他方法参数有差异，是需要过滤的数据的16进制字符串字符长度，且长度值需是偶数: 比如要掩码EPC的数据：
    EPC :E280FE9889895674
    如果要掩码其中的"FE98"那么这里的长度填 16（bits）
    又或者EPC：00001234567898762345
    如果要掩码其中的"567898762345"那么这里的长度填 48（bits）
    datasMaskString要过滤的内容，十六进制数据。（ 数据长度需是十六进制字符串2个字符的倍数）

    通过异步方式，检测本地的固件包，判断固件版本，返回是否需要升级的标识。

    void checkUpgrade(Context context, UpgradeSource source, FirmwareUpgradeCallback callback);

    sourceUpgradeSourceRFUpgradeManager.UpgradeSource source = null;
    assets 相对路径，
    如 `"bin/xxxx.zip"
    source = RFUpgradeManager.UpgradeSource.fromAssets("bin/" + "xxxx.zip");
    从本地文件系统读取；文件须存在且可读: source = RFUpgradeManager.UpgradeSource.fromLocalPath(getFilesDir()+"/files/"+"xxxx.zip");
    myCallbackFWUpdateCallback见下方说明

    示例

    java
    RFUpgradeManager.getInstance().checkUpgrade(
context,RFUpgradeManager.UpgradeSource.fromAssets("bin/your_firmware.zip"),
new FirmwareUpgradeCallback() {
@Override
public void onCheckResult(UpgradeCheckResult result, UpgradeInfo info) {
if (!result.checkPassed) {
// 处理失败：result.errorMessage
return;
}
if (!result.hasUpgrade) {
// 已是最新
return;
}
// 需要升级：使用 info 展示详情
RFUpgradeManager.getInstance().showConfirmDialog(
activity, info, "", "", confirmListener);
}
// onStepChanged / onUpgradeFinished / onError ...
});

    FWUpdateCallback回调方法有下面4个：

    - onCheckResult(UpgradeCheckResult result, UpgradeInfo info) 触发于： checkUpdate()；

    • onStepChanged(UpgradeStepEvent event) 触发于：startUpgrade()的升级过程中；
    • onUpgradeFinished(boolean success, String message) 升级流程全部结束:

    success:true 升级成功 false 升级失败 ，

    message：升级成功或失败的原因

    • onError(int errorCode, String message) 校验升级或者开始升级过程，回调出现的错误。

    成功/失败均通过 `onCheckResult(result,info)回调

    UpgradeCheckResult

    要关注以下字段：

    • checkPassed： boolean 是否检测/解压通过；
    • hasUpgrade： Boolean 是否至少有一个固件需要升级 ；
    • errorMessage：String checkPassed=false 时的失败原因；
    • errorCode：int 错误码，0 表示无错误 。

    主要判断：

    4.12.4、QueryMemBank

    QueryMemBank 枚举，供 setQueryMemoryBank() / getQueryMemoryBank() 使用。

    QueryMemBank读取的 Bank
    EPCEPC 查询
    参数：startAddress = 0，readLen = 0
    行为：读取默认长度 EPC（不含 CRC 与 PC 头）
    EPC_TIDEPC + TID 混合查询
    参数：startAddress = TID 起始字地址（0–5），readLen = TID 读取长度（1–6 字）
    回调：EPC → ReadTag.epcId；TID → ReadTag.memId
    EPC_USEEPC + USER 混合查询
    参数：startAddress = USER 起始字地址（≥ 0），readLen = USER 读取长度（1–32 字）
    回调：EPC → ReadTag.epcId；USER → ReadTag.memId
    EPC_RESERVEDEPC + RESERVED（Password）混合查询
    参数：startAddress = RESERVED 起始地址（0–3），readLen = 密码读取长度（1–4 字）
    回调：EPC → ReadTag.epcId；RESERVED → ReadTag.memId
    FASTTIDImpinj FastTID 快速模式
    参数：startAddress = 0，readLen = 0（固定）
    自动读取完整 96 位 TID（字地址 0–5）写入 ReadTag.memId
    兼容性：仅支持 Impinj Monza® 系列标签
    EPC_EPCEPC + EPC 双区查询
    参数：startAddress = 第二 EPC 起始地址，readLen = 第二 EPC 读取长度
    第一 EPC（默认长度）→ ReadTag.epcId；第二 EPC 段 → ReadTag.memId
    典型应用：读取 PC 位或部分 EPC 校验
    BIDBID 查询（需特殊标签支持）
    参数：startAddress = 0，readLen = 0（固定）

    6.6、补充说明

    1. 长距（带手柄）设备控制扫描头出光(针对非蓝牙设备)

    RFIDSDKManager.getInstance().enableScanHead(boolean isOpen);

    说明：此方法是针对长距带手柄RFID设备，控制手柄上的按键，是否触发扫码头扫码

    参数 类型 说明 isOpen boolean true,手柄按键触发扫码；false，手柄按键不触发扫码

    2. 蓝牙设备，使用NFC连接方式时，读到的信息解析MAC地址

    String mac = NFCUtils.getBleMac(NdefMessage ndefMessage);

    说明：传入NFC拿到的NdefMessage 对象，方法返回的是蓝牙设备的MAC地址，拿到地址后，可以传入 initBTToMac(Context context, String mac, InitListener listener);方法中的 mac 传参。

    参数 类型 说明 ndefMessage NdefMessage NFC拿到的NdefMessage 对象

    建议

    • init()方法和release()方法成对出现，退出应用时调用release()断开RFID连接。
    • 根据错误码对照表进行故障处理。
    • 关于开启SDK日志: 建议使用UlogManager.enableLog(true); true:开启日志 false:关闭日志；用此方法在调用本SDK前先设置一次，日志文件会保存在 /sdcard/Download/rfidLog ，记录文件需要存储权限。
