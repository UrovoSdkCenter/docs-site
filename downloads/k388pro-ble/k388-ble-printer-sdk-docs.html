概述

SDK 简介

K388 BLE Printer SDK 用于通过 蓝牙低功耗（BLE） 连接 Urovo K388 / K388Pro 打印机。对外入口为 com.urovo.printer.ble.BlePrinterManager。打印指令为 CPCL，坐标单位为点（dot），203 dpi 下约 8 点 = 1 mm。

getSDKVersion() 返回：Urovo K388 BLE Printer SDK v1.0.0。组包 version() 返回：V1.5。

本版本 不含 RFID。

版本变更

当前文档对应 SDK v1.0.0。print-ble 工程内未提供独立 ChangeLog。如需补充历史版本变更，请提供后更新本节。

核心能力

  • 按 MAC 连接 / 断开 BLE 打印机
  • 组 CPCL 页面：文字、线条、框、一维码、二维码、图片
  • printByData / printByGzipData / printByText 下发数据
  • 查询打印机状态与固件版本
  • 页内参数与持久化打印设置
  • 固件升级（带进度回调）

适用场景

  • 手机或平板通过蓝牙打印标签 / 票据
  • 扫描后现场打印条码或二维码
  • 远程维护：查状态、改黑度、升级固件

接入

获取 SDK

推荐 fat jar（含组包类）：

gradle
implementation files('libs/UK388PrintBleLibrary_fat_v1.0.0.jar')

或工程模块：

gradle
implementation project(':print-ble')

生成 jar：

bash
./gradlew :print-ble:compileDebugJavaWithJavac :print-ble:makeJar
./gradlew :print-ble:makeFatJar

输出目录：print-ble/build/libs/。仅 makeJar 时需另外引入 print 组包 jar。

工程配置

在应用 AndroidManifest.xml 声明并动态申请：

xml
<uses-permission android:name="android.permission.BLUETOOTH" android:maxSdkVersion="30" />
<uses-permission android:name="android.permission.BLUETOOTH_ADMIN" android:maxSdkVersion="30" />
<uses-permission android:name="android.permission.BLUETOOTH_CONNECT" />
<uses-permission android:name="android.permission.BLUETOOTH_SCAN" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
系统运行时权限
Android 12+BLUETOOTH_CONNECT、BLUETOOTH_SCAN
Android 11 及以下扫描时需定位权限

BLE 特征（SDK 内置，应用无需配置）：

方向UUID
打印机 → App（Notify）0000fff1-0000-1000-8000-00805f9b34fb
App → 打印机（Write）0000fff2-0000-1000-8000-00805f9b34fb

无 API Key。混淆 keep com.urovo.printer.ble. 与 com.urovo.printer.。

初始化

java
BlePrinterManager printer = BlePrinterManager.getInstance(context);

首次必须传入 Context。无鉴权配置项。

快速开始

java
BlePrinterManager printer = BlePrinterManager.getInstance(context);
try {
    printer.connect("AA:BB:CC:DD:EE:FF");
    printer.pageSetup(384, 240);
    printer.drawText(16, 16, "K388Pro", 2, 0, 0, false, false);
    printer.drawBarCode(16, 64, "123456789012", 1, 0, 2, 72);
    byte[] data = printer.printByte(0, 1);
    printer.printByGzipData(data);
} catch (PrinterException e) {
    e.printStackTrace();
} finally {
    printer.disconnect();
}

步骤：初始化 → connect(mac) → 组页 → printByte → printByData 或 printByGzipData → 断开。

成功标志：发送接口返回 true，打印机出纸。draw* 不会单独出纸。

注意事项与 FAQ

注意事项

  • draw* 只组页，必须 printByData / printByGzipData / printByText 才会打印。
  • BLE 收发和固件升级放子线程。
  • 文本 GBK 编码。
  • 页宽建议不超过可打宽度（约 384~400 点）。
  • 升级后必须重新 connect。
  • 本版本无 RFID 接口。
  • 组页为 CPCL，不是 ZPL 封装。

FAQ

Q: printByData 在蓝牙版能直接调用吗？

A: 可以。先 connect，再组页或直接传入字节。

Q: 调用了 drawText 为什么没出纸？

A: 继续调用 printByte，再 printByData 或 printByGzipData。

Q: 是否支持 ZPL？

A: 组页 API 为 CPCL。若固件接受 ZPL，仅可用 printByText/printByData 发原文。

Q: 连接成功但不打印？

A: 检查蓝牙权限、MAC，并用 getPrinterStatus() 查看缺纸/开盖。

Overview

Introduction

K388 BLE Printer SDK connects Urovo K388 / K388Pro printers over Bluetooth Low Energy. The public entry is com.urovo.printer.ble.BlePrinterManager. Commands are CPCL. Coordinates are dots; at 203 dpi about 8 dots = 1 mm.

getSDKVersion() returns Urovo K388 BLE Printer SDK v1.0.0. Page-builder version() returns V1.5.

This release does not include RFID.

Version history

This document matches SDK v1.0.0. The print-ble module has no standalone ChangeLog. Provide historical notes if they should appear here.

Key Features

  • Connect / disconnect by MAC over BLE
  • Build CPCL pages: text, lines, boxes, 1D/2D barcodes, images
  • Send with printByData / printByGzipData / printByText
  • Query printer status and firmware version
  • Job settings and persistent print registers
  • Firmware upgrade with progress

Use Cases

  • Phone or tablet label / receipt printing over BLE
  • Print barcodes or QR codes after a scan
  • Maintenance: status, darkness, firmware upgrade

Notes & FAQ

Notes

  • draw* only builds the page; you must send with printByData / printByGzipData / printByText.
  • Run BLE I/O and firmware upgrade off the UI thread.
  • Text is GBK.
  • Keep page width within the printable width (about 384–400 dots).
  • After upgrade, call connect again.
  • No RFID APIs in this version.
  • Page APIs are CPCL, not a ZPL wrapper.

FAQ

Q: Can printByData be called directly on the BLE SDK?

A: Yes. Connect first, then send page bytes or any CPCL payload.

Q: I called drawText but nothing printed.

A: Call printByte, then printByData or printByGzipData.

Q: Is ZPL supported?

A: Page APIs are CPCL. Raw ZPL may be sent with printByText/printByData only if firmware accepts it.

Q: Connected but no print?

A: Check Bluetooth permissions and MAC, then getPrinterStatus() for paper or cover errors.
