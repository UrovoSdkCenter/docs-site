    1、Overview

    1.1、Introduction

    K388 Printer SDK targets the onboard printer of Urovo K388 / K388Pro. The public entry is com.urovo.printer.UPrinterManager. Commands are CPCL. Coordinates are dots; at 203 dpi about 8 dots = 1 mm.

    getSDKVersion() returns Urovo K388 Printer SDK v1.0.0. Page-builder version() returns V1.5.

    This SDK does not use TCP 9100. It talks to the local print service through a LocalSocket named PrinterLocalServerSocket.

    1.2、Version history

    This document describes SDK v1.0.0 (same string as getSDKVersion()).

    1.3、Key Features

    • Connect the onboard printer and query status (out of paper, cover open)
    • Build CPCL pages: text, lines, boxes, 1D/2D barcodes, images
    • Send raw bytes or GBK text
    • Job settings and persistent registers (darkness, mode, multi-copy delay, rewind)
    • RFID read/write and power
    • Firmware version query and firmware upgrade

    1.4、Use Cases

    • On-device label / receipt printing
    • Print barcodes or QR codes after a scan
    • Write RFID then read back to verify
    • Production or maintenance firmware upgrade

    2、Integration

    2.1、Obtain the SDK

    Add the print module:

    gradle
    implementation project(':print')

    Or copy the JAR:

    gradle
    implementation files('libs/UK388PrintLibrary_v2.3.1.jar')

    Build the JAR:

    bash
    ./gradlew :print:compileDebugJavaWithJavac :print:makeJar

    Output directory: print/build/libs/.

    2.2、Project Setup

    • The module AndroidManifest.xml declares no extra permissions. Request storage (firmware file) in the app as needed.
    • Keep com.urovo.printer.** when obfuscating.
    • No API key.

    2.3、Initialization

    java
    UPrinterManager printer = UPrinterManager.getInstance(context);

    Or:

    java
    UPrinterManager.initialize(context);
UPrinterManager printer = UPrinterManager.getInstance();

    The first call must pass a Context. No auth settings.

    3、Quick Start

    java
    UPrinterManager printer = UPrinterManager.getInstance(context);
try {
    printer.connect();
    printer.pageSetup(384, 240);
    printer.drawText(16, 16, "K388", 2, 0, 0, false, false);
    printer.drawBarCode(16, 64, "123456789012", 1, 0, 2, 72);
    byte[] data = printer.printByte(0, 1);
    boolean ok = printer.printByData(data);
} catch (PrinterException e) {
    e.printStackTrace();
} finally {
    printer.disconnect();
}

    Flow: getInstance → connect → pageSetup / draw* → printByte → printByData → disconnect.

    Success: printByData returns true and paper feeds. pageSetup / drawText do not print by themselves.

    6、Notes & FAQ

    6.1、Notes

    • draw* only builds the page; printByData / printByText actually print.
    • Text is encoded as GBK.
    • Keep page width within the printable width (often about 384–400 dots). print(int skip) inserts CENTER.
    • Do not block the UI thread for firmware upgrade, RFID, or print I/O.
    • Do not connect / print / change settings during upgrade.
    • This SDK talks to the onboard print service, not TCP 9100. Page APIs are CPCL, not ZPL.

    6.2、FAQ

    Q: I called drawText but nothing printed.

    A: Call printByte (or print) then printByData.

    Q: Is ZPL supported?

    A: Page APIs are CPCL. Raw ZPL can be sent with printByText/printByData only if firmware accepts it.

    Q: What if printByData is called while disconnected?

    A: It returns false and does not throw.

    Q: Blank space on the right of an image?

    A: Page width may exceed printable width. Try about 384 dots and match label orientation with pageSetup.

    1、概述

    1.1、简介

    K388 Printer SDK 面向 Urovo K388 / K388Pro 本机内置打印机。对外入口为 com.urovo.printer.UPrinterManager。打印指令为 CPCL，坐标单位为点（dot），203 dpi 下约 8 点 = 1 mm。

    getSDKVersion() 返回 Urovo K388 Printer SDK v1.0.0。组包 version() 返回 V1.5。

    本 SDK 不使用 TCP 9100，通过本机 LocalSocket（PrinterLocalServerSocket）与打印服务通信。

    1.2、版本变更

    本文档描述 SDK v1.0.0（与 getSDKVersion() 返回值一致）。

    1.3、主要能力

    • 连接本机打印机，查询缺纸、开盖等状态
    • 组 CPCL 页面：文字、线条、框、一维码、二维码、图片
    • 下发原始字节或 GBK 文本
    • 页内打印参数与持久化寄存器设置（黑度、模式、多张延时、回退）
    • RFID 读写与功率设置
    • 固件版本查询与固件升级

    1.4、适用场景

    • 设备侧标签 / 票据打印
    • 扫描后现场打印条码或二维码
    • 标签 RFID 写入后读回校验
    • 产线或运维场景的固件升级

    UPrinterManager printer = UPrinterManager.getInstance(context);

    图片页必须用 printByte；大数据可先 GZIPFrame.codec。

    5.3、RFID 写入

    java
    boolean ok = printer.rfidWrite(1, 0x00000000, 4, epc, epc.length);
String code = printer.rfidWriteWithResp(1, 0x00000000, 4, epc, epc.length);
byte[] buf = new byte[epc.length];
printer.rfidRead(1, 0x00000000, 4, buf, buf.length);

    从 offset=4 写 EPC 区时不会自动更新 PC 长度字段；长度变化需自行更新 PC。

    6、注意事项与 FAQ

    6.1、注意事项

    • draw* 只组页，必须 printByData / printByText 才会打印。
    • 文本按 GBK 编码。
    • 页面宽度不要超过打印头可打宽度（常见约 384～400 点）。print(int skip) 组包会插入 CENTER。
    • 固件升级、RFID、打印请避免阻塞 UI 线程。
    • 升级过程中禁止 connect / 打印 / 改设置。
    • 本 SDK 面向本机打印服务，不是网络 9100 端口，组页 API 不是 ZPL。

    6.2、FAQ

    Q: 调用了 drawText 为什么没出纸？

    A: 还需 printByte（或 print）再 printByData。

    Q: 是否支持 ZPL？

    A: 组页 API 为 CPCL。若固件接受 ZPL，仅可用 printByText/printByData 发送原文，SDK 不封装 ZPL。

    Q: printByData 未连接会怎样？

    A: 返回 false，不会抛异常。

    Q: 图片右侧出现空白？

    A: 页宽可能大于可打宽度，尝试将宽度降到约 384 点，并确认标签方向与 pageSetup 一致。
